# Hairline Studio — project context

A visual editor for isometric line figures that react to the mouse pointer, inspired by Hairline (https://hairline.lucasmarkes.com) by Lucas Marques. It is an independent project with its own engine: it does not use or bundle Hairline's code and is not affiliated with it.

Public repo: https://github.com/zuppdev/hairline-studio · Live: https://zuppdev.github.io/hairline-studio/

## What's here

- `index.html` — the entire app. No build step, no runtime dependencies. `npm start` serves it on :8765.
- `examples/` — the four presets exported as standalone HTML. Generated by `npm run examples`; never hand-edit.
- `tests/` — Playwright suite (Chromium, Firefox, WebKit): `engine.spec.js`, `studio.spec.js`, `examples.spec.js`. Uses the `window.__studio` hook.
- `scripts/serve.mjs` — zero-dependency static server. `scripts/build-examples.mjs` — exports each preset; `--check` fails if stale.
- `docs/screenshot.png` — README screenshot and og:image.
- `.github/workflows/ci.yml` — tests + examples check on every push/PR; on `main`, deploys `index.html`, `examples/`, `docs/` to Pages (build_type=workflow).

## How the engine works

Everything lives in `hairlineMount(svg, figure, options)` inside `index.html`. The exported files embed this same function (via `hairlineMount.toString()`), so any change to it changes both the studio and future exports.

- A figure is `{name, plate, motion, parts}`. Each part is `{kind: 'box'|'cyl', x, y, z, w, d, h, still?}` in grid units.
- Isometric projection: `screenX = (x − y)·cos30°·S`, `screenY = (x + y)·sin30°·S − z·S` with `S = 40`. View rays run along (1, 1, 1).
- Each frame: distance from pointer (or rank, for "height"/"across" picking) → falloff target 0..1 → snap / ease / damped spring on a **fixed 60 Hz step** (accumulator) → apply effect scaled by `amount × (0.3 + 1.4 × intensity)` → depth order → redraw. Redraw is skipped when no part moved and nothing is dirty.
- Depth order (`depthOrder`): pairs whose screen hexagons overlap (ranges of x−y, z−y, z−x) are ordered by the axis plane separating them (low side is behind), then topologically sorted. Centre-point sorting was wrong for long parts; don't go back to it.
- `update(fig, keepView)`: the studio passes `keepView` while dragging. Refitting the viewBox mid-drag moves the frame under the pointer and makes the part run away.
- The tour clock starts at the first rAF timestamp it sees (Firefox rAF time can precede `performance.now()`).
- Ripple delay samples the pointer history so far parts react later. `still: true` parts never move and are excluded from tours and ranking.
- Colors come from CSS custom properties: `--hl-plate`, `--hl-hi`, `--hl-edge`, `--hl-mid`, `--hl-lo`, `--hl-stroke`, `--hl-sel`. `prefers-reduced-motion` turns spring into ease.

## Studio features

Presets, Edit/Preview modes, drag to move (Shift-drag for height, Alt to skip snapping), arrow/PgUp/PgDn nudging, Esc deselects, duplicate, remove, repeat-into-a-row, undo/redo (discrete edits force their own step; continuous ones group within 600 ms), autosave to localStorage, Save/Open `.hairline.json`, Open also re-imports exported HTML (parses the `var FIGURE = ...;` line). Every incoming figure (autosave, file, export) goes through `clean()`, which clamps to the control ranges.

## Conventions

- Keep it a single dependency-free `index.html`; ES5 syntax in the engine (a test enforces it).
- After changing the engine: `npm run examples`, commit the result. CI fails otherwise.
- Run `npm test` before pushing. Add user-facing changes to `CHANGELOG.md` under Unreleased.
